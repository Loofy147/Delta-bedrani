# Deep audit — Delta-bedrani — 2026-09-27

## Scope

This audit re-checks the mathematical definitions, exact algorithms, API invariants, tests, repository lineage, CI, and ecosystem claims before merging PR #1.

## Findings and repairs

### 0. Value invariant

The constructor previously accepted arbitrary nonempty families under a class named `DeltaMatroid`. It now validates symmetric exchange by default. The matching constructor uses an internal validated path because its construction is theorem-backed.

### A. Mathematical definitions

1. **Evenness was incorrectly implemented.**
   The old implementation required every feasible set to have even cardinality.
   Correct definition: all feasible sets have the same parity.
   Fixed in `DeltaMatroid.is_even()`.
   Matching delta-matroids remain the normal even subclass because their feasible sets are vertex sets covered by perfect matchings.

2. **Wenzel strong exchange check**
   The verifier now tests the even-delta-matroid strong simultaneous exchange form:
   for each A,B and x in A Delta B, find y in (A Delta B)\{x} such that both A Delta {x,y} and B Delta {x,y} are feasible.

3. **Exchange distance opportunity**
   Once the input is known to be an even delta-matroid, Wenzel exchange gives a path that reduces |A Delta B| by 2 at every step. Since every basis-graph edge changes two elements, the graph distance is exactly |A Delta B|/2.
   Current engine still uses BFS so that the graph layer remains an independently testable computational backend. A theorem-driven distance/path backend is the next optimization and must not be exposed as a theorem for arbitrary unverified families.

### B. Exact matching layer

1. `MatchingGraph.feasible_masks()` is deterministic subset-DP.
2. Independent brute-force matching recursion was used on 25 random n=6 graphs across all subsets; no mismatches were found.
3. Exhaustive n=4 and n=5 graph tests cover all 1088 labeled simple graphs and verify evenness, symmetric exchange, and Wenzel strong exchange.
4. Large explicit `feasible_family()` materialization is intentionally not the authority path for n around 24; bitmask tables are the scalable representation.

### C. Finite-field algebra layer

1. `det_mod_p` and `inverse_mod_p` use exact integer arithmetic only.
2. The modulus is now explicitly required to be an odd prime.
3. Matrix entries are required to be integers.
4. `GlobalTutteMatrix` validates canonical vertex indices, square shape, zero diagonal, and skew symmetry.
5. A global sampled matrix is shared across principal minors and PPT operations.
6. A nonzero evaluated Tutte determinant is a one-sided certificate of perfect matchability.
7. A randomized zero remains UNKNOWN and is never treated as a proof of infeasibility.
8. The K3 disjoint-union K3 regression remains an exact-zero test over 100 sampled matrices.
9. PPT identities are tested only when the pivot block is invertible.

### C2. Exact matrix object invariant

The Tutte object now validates odd-prime modulus, canonical vertex indexing, square shape, integer entries, zero diagonal, and skew symmetry at construction. This prevents a manually created object from carrying a state that is not an exact finite-field Tutte matrix.

### D. Exchange engine

1. Feasible subsets are represented by bitmasks; edges are generated lazily.
2. Even families validate parity uniformity.
3. Non-normal families are supported; the engine no longer assumes the empty set is feasible.
4. Connectivity, shortest paths, and exact all-pairs diameter are separate operations.
5. Exact diameter has an explicit feasible-vertex guard rather than silently becoming impractical.
6. A direct cross-check compares lazy neighbors with the explicit delta-matroid exchange relation.

### E. Packaging and CI

1. Explicit setuptools src-package discovery was added.
2. GitHub Actions tests Python 3.10–3.13.
3. Workflow run 36331349628 completed successfully in all four matrix jobs before the latest hardening commits. A new workflow is triggered by the latest hardening changes and must be checked again before merge.
4. A prior feature-branch tree construction accidentally dropped CI and benchmark documentation. The compare-diff audit detected this. The files were restored explicitly. Future changes should be made with sequential content updates or a single complete tree rooted at the correct base.

## Ecosystem / novelty boundary

The repository should not claim that no delta-matroid implementation exists anywhere.

SageMath's documented matroid reference remains centered on classical matroids, while an August 2026 Jacobian issue proposes exact delta-matroid support including feasible-set exchange, twists, minors, width, and binary principal-minor constructions. Therefore the defensible scope is narrower:

> Delta-bedrani provides a focused exact research kernel combining deterministic matching-pattern enumeration, finite-field Tutte/PPT certificates, exchange-graph experiments, and reproducible evidence logging.

That architecture and its verification discipline are the relevant object of novelty, not the existence of the abstract data structure itself.

### Theorem-aware exchange path

The implementation now exposes an exact distance/path backend based on SEA + parity, with BFS retained as an independent computational oracle. This is a derived theorem-backed optimization, not an empirical speed claim.
